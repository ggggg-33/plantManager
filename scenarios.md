# Сценарии использования: Система учета растений

## Название варианта использования: Добавление нового растения в коллекцию

**Описание**
**Цель:** Позволить пользователю добавить новое растение в коллекцию с автоматической настройкой параметров ухода на основе сезона и вида растения.

**Актёры:** Растениевод

**Триггер:** Пользователь приобретает новое растение или решает начать его учет в системе

**Предварительные условия:**
- приложение открыто
- выбран источник данных (CSV или PostgreSQL)
- все поля формы доступны для редактирования

**Основной поток выполнения:**
1) Пользователь вводит название растения
2) Пользователь вводит базовую частоту полива, высоту растения, обычный рост растения в месяц
3) Пользователь устанавливает дату посадки и, при необходимости, даты последнего полива и последней пересадки через DatePicker
4) Пользователь нажимает кнопку «Добавить»
5) Система валидирует введенные данные (высота, рост и частота полива должны быть положительными числами)
6) Система автоматически корректирует частоту полива в зависимости от текущего сезона
7) Система устанавливает текущую дату как дату последнего полива
8) Система добавляет растение в выбранное хранилище
9) Таблица растений обновляется, поля формы очищаются

**Альтернативы:**
A1: Ошибка при вводе числовых параметров
1) Пользователь вводит некорректные значения высоты, частоты или роста полива
2) Система отображает сообщение «Некорректные числовые параметры»
3) Пользователь исправляет ввод и повторяет действие

**Постусловие:**
1) Новое растение добавлено в базу и отображается в таблице
2) Система автоматически рассчитала параметры ухода с учетом сезона

## Название варианта использования: Редактирование данных о растении

**Описание**
**Цель:** Позволить пользователю изменить параметры существующего растения в коллекции

**Актёры:** Растениевод

**Триггер:** Пользователь обнаружил изменения в состоянии растения или хочет скорректировать параметры ухода

**Предварительные условия:**
- приложение открыто
- таблица растений содержит хотя бы одну запись
- пользователь выбрал растение из таблицы

**Основной поток выполнения:**
1) Пользователь выбирает растение в таблице
2) Поля формы автоматически заполняются текущими значениями параметров растения
3) Пользователь вносит изменения в название, высоту, рост или частоту полива
4) Пользователь нажимает кнопку «Изменить»
5) Система проверяет корректность введенных данных
6) Система пересчитывает параметры ухода с учетом сезонности
7) Изменения сохраняются в выбранном источнике данных
8) Таблица обновляется, поля очищаются

**Альтернативы:**
A1: Ошибка в данных
1) Пользователь вводит некорректные числовые значения
2) Система отображает сообщение об ошибке
3) Пользователь исправляет данные и повторяет действие

**Постусловие:**
1) Данные растения обновлены в источнике
2) Параметры ухода пересчитаны с учетом изменений

**Триггер:** Пользователь хочет удалить растение из учета

**Предварительные условия:**

## Название варианта использования: Диагностика здоровья растения

**Описание**
**Цель:** Проанализировать симптомы растения и предоставить рекомендации по лечению

**Актёры:** Растениевод

**Триггер:** Пользователь заметил признаки ухудшения состояния растения

**Предварительные условия:**
- приложение открыто
- пользователь выбрал растение из таблицы

**Основной поток выполнения:**
1) Пользователь выбирает растение в таблице
2) Пользователь описывает симптомы в специальном поле (например, «желтые листья», «вялые стебли»)
3) Пользователь нажимает кнопку «Диагностировать»
4) Система анализирует симптомы и сопоставляет их с известными заболеваниями
5) Система отображает диагностический отчет с возможными причинами и рекомендациями по лечению
6) Статус здоровья растения обновляется в системе

**Альтернативы:**
A1: Симптомы не указаны
1) Пользователь нажимает «Диагностировать» без описания симптомов
2) Система использует текущий статус здоровья растения для диагностики

**Постусловие:**
1) Получен диагностический отчет
2) Статус здоровья растения обновлен
3) Пользователь получил рекомендации по лечению

## Название варианта использования: Поиск и фильтрация растений

**Описание**
**Цель:** Позволить пользователю быстро находить растения в коллекции по различным критериям

**Актёры:** Растениевод

**Триггер:** Пользователь вводит текст в поле поиска или выбирает критерий сортировки

**Предварительные условия:**
- приложение открыто
- в таблице имеются данные о растениях

**Основной поток выполнения:**
1) Пользователь вводит текст в поле поиска
2) Система в реальном времени фильтрует растения по названию, виду и статусу здоровья
3) Пользователь выбирает тип сортировки из выпадающего списка (по имени, высоте, дате посадки)
4) Система применяет выбранную сортировку и обновляет таблицу
5) При очистке поля поиска отображаются все растения

**Альтернативы:**
отсутствуют

**Постусловие:**
1) Таблица отображает отфильтрованные и отсортированные растения
2) Пользователь может легко найти нужное растение

## Название варианта использования: Смена источника хранения данных

**Описание**
**Цель:** Позволить пользователю переключаться между различными хранилищами (CSV, PostgreSQL) без потери данных

**Актёры:** Растениевод

**Триггер:** Пользователь выбирает нужный источник данных из списка и нажимает «Выбрать»

**Предварительные условия:**
- приложение работает
- интерфейс активен
- доступны реализации DAO для выбранных источников

**Основной поток выполнения:**
1) Пользователь открывает выпадающий список источников данных
2) Выбирает один из вариантов: «CSV», «PostgreSQL»
3) Нажимает кнопку «Выбрать»
4) Система инициализирует соответствующий DAO
5) Таблица обновляется данными из выбранного хранилища
6) Все последующие операции выполняются с выбранным источником

**Альтернативы:**
A1: Ошибка подключения к PostgreSQL
1) Подключение к базе данных не удалось
2) Система отображает сообщение об ошибке
3) Система автоматически переключается на CSV-хранилище

**Постусловие:**
1) Программа работает с выбранным хранилищем
2) Данные в таблице соответствуют выбранному источнику
